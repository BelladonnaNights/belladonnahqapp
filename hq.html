How the agents plug in (for whoever builds the backend)
The cards read these Firestore collections live. Anything that writes to them (a Cloud Function, a scheduled task, your other Claude account) lights up the matching card. Everything also works by hand from inside each card.
agent_leads   {site, client, contact, eventType, eventDate (YYYY-MM-DD), location,
               headcount, budget, message, link, stage: new|quoted|booked|lost,
               receivedAt (ms), quotedAt, quotedPrice, bookedPrice, lostReason,
               nudges: {n1, n2}, repliedAt, source}
agent_drafts  {leadId, agent: quill|vesper|mirror, kind: reply|n1|n2|review,
               body, label, status: pending|approved|skipped, createdAt (ms)}
agent_sites   {name, feesPaid, profileRefreshed (ms), active}
agent_venues  {name, city, address, evidence, pitch, stage: target|followup|yes|no|onboarding,
               contactName, contact, trialDate, followUpOn (YYYY-MM-DD), noUntil (ms),
               verify, visits: {<ms>: {at, who, said, outcome}}}
agent_config  docs: pricing {text} · voice {text} · outreach {terms} · sable {digest, decisions, loadedAt}
Firestore rules: add these five collections next to your other HQ rules, for example
match /agent_leads/{id}   { allow read, write: if isAdmin(); }
match /agent_drafts/{id}  { allow read, write: if isAdmin(); }
match /agent_sites/{id}   { allow read, write: if isAdmin(); }
match /agent_venues/{id}  { allow read, write: if isAdmin(); }
match /agent_config/{id}  { allow read, write: if isAdmin(); }
